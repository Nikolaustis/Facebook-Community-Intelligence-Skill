# Facebook Game Group Monitor Skill V8.0.0

V8.0.0 is the stable **Game-centric** release line. It preserves the proven Phase 1 → Phase 1.5 → Phase 2 workflow and focuses on reliability, cross-machine deployment, multilingual metric parsing, and failure containment.

## Highlights

- Hardened `phase1` / `phase2` entrypoints with fail-closed runtime patch contracts.
- Added `npm run doctor` environment, browser, CDP, profile, and login-readiness diagnostics.
- Fixed premature rejection when the Phase 1 card member count is missing or unparseable.
- Added shared multilingual parsing for group size and activity metrics, including `K`, `M`, and `万`-style quantities.
- Cache only successful About/discussion fetches so transient failures do not poison later processing.
- Improved Chrome/Edge executable discovery and machine-local dedicated browser-profile handling.
- Strengthened Facebook login-state classification and positive authenticated-state checks.
- Unified reliability handling across foreground, background, scheduled Phase 2, and handoff execution paths.
- Added reliability regression tests and collector-source contract tests.
- Aligned release metadata to `8.0.0` in `package.json`, `package-lock.json`, `SKILL.md`, and Phase 1 runtime outputs.

## Compatibility

- Existing `games`, `aliases`, `sibling_titles`, `ip_roots`, Phase 1.5, language/region, threshold, checkpoint, semantic resolver, and Excel workflows remain Game-centric and compatible.
- Existing run data and machine-local credentials/configuration should be preserved when updating.
- No Subject / Community / Match architecture, Community Intelligence benchmark, AI evaluation, or V2 example dataset is included in this release.

## Installation / update

From the repository root:

```powershell
npm ci
npm run doctor
npm test
```

For an existing local installation, preserve machine-specific configuration, browser profiles, credentials, and run data that are intentionally excluded from Git.

## Main workflow

```powershell
npm run login
npm run validate-login

npm run phase1 -- --games "Game A,Game B" --out-dir ".\runs\example" --config ".\task_config.json"

npm run phase15 -- --index ".\runs\example\phase1_index.json" --config ".\task_config.json" --out-dir ".\runs\example"

npm run phase2 -- --index ".\runs\example\phase1_index.json" --config ".\task_config.json"
```

Phase 2 can also invoke or reuse Phase 1.5 automatically from the original Phase 1 index.

## Reliability model

V8.0.0 keeps the mature collectors intact and places verified reliability controls around them:

- unknown card metrics continue to page-level validation rather than being treated as `<100`;
- transient About/discussion failures are not reused as valid cache entries;
- browser and login prerequisites are checked explicitly;
- background/scheduled entrypoints share the hardened execution path;
- regression and contract tests fail closed when collector source assumptions change.

See [`RELIABILITY_HARDENING.md`](RELIABILITY_HARDENING.md) for implementation details.

## Release boundary

V8.0.0 is intentionally the final mature **Game-centric** baseline.

The later generalized Community Intelligence architecture is a separate major-version evolution and is not part of this historical release.
