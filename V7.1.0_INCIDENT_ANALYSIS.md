# V7.1.0 Incident Analysis

## Observed behavior

V7.0.1 Phase 1.5 rejected group names that visibly contained the complete English game title when the final English character was immediately followed by Chinese, Thai, Lao, Arabic, or another non-Latin character.

Representative examples:

- `Sailor Piece水手寶石中文交易討論區`
- `All Star Tower Defenseซื้อขาย...`
- `Pet Simulator 99中文讨论/交易群`

## Root cause

`buildPhraseRegex()` used `\p{Letter}` at both phrase boundaries. Under Unicode, Han and Thai characters are letters, so a non-Latin suffix was treated as continuation of the English token rather than a valid script transition.

The same matcher also did not allow Unicode format controls such as zero-width space (`U+200B`) between title tokens.

## Correction

For phrases made only of Latin letters and numbers, V7.1.0 treats only Latin letters and numbers as continuation characters. Other scripts form valid boundaries. Phrases containing non-Latin text retain the Unicode-wide boundary and localized compact fallback.

The rule does not weaken continuation protection: `Pieces`, `DefenseX`, `PieceMN`, `99100`, and `GAG2` as a match for `GAG` remain blocked.
